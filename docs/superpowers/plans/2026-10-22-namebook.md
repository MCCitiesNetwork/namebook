# Namebook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Namebook, a Paper plugin and published API that resolves Minecraft player names and UUIDs in both directions.

**Architecture:** `namebook-api` holds the public `Namebook` interface. `namebook-core` (no Bukkit) holds name rules, the cache, the rate limiter, MariaDB storage, the playerdb.co and Mojang sources, the user-cache importer and the lookup chain that ties them together. `namebook-paper` is the plugin: configs, the server-cache source, the join recorder, commands and service registration.

**Tech Stack:** Java 25, Gradle 9 Kotlin DSL, Paper API `26.3.build.211-stable`, Incendo Cloud 2.0.1, Configurate YAML 4.2.0, MyBatis 3.5.19, MariaDB Connector/J 3.5.6, plugin-infrastructure 1.0.0-SNAPSHOT, Jackson 2.18.2, JUnit 5.11.4, Mockito 5.23.0, Testcontainers 2.0.x (MariaDB 11.7).

**Spec:** `docs/superpowers/specs/2026-10-22-namebook-design.md`

## Review Focus

1. **Two players swap names in one restart window** (A takes B's old name while B's row still holds it, or both join at once): the join must never fail on the unique key; the newest join wins. Test in Task 4.
2. **Remote sources misbehave** (HTTP 429/500, malformed JSON, a body whose UUID or name doesn't match the request, a hung connection): each counts as unknown for that source and the chain moves on; nothing throws. Tests in Task 5.
3. **Bulk calls with duplicates and mixed case** (`["Steve","steve","STEVE"]`): one database query, every key present with the caller's spelling, all mapped to the same UUID. Test in Task 7.
4. **Hostile or odd names** (`%`, `a b`, 40 characters, empty, `.` alone, `_`): invalid ones return empty without touching any source; `_` is a valid name character and must be matched exactly, never as a SQL wildcard. Tests in Tasks 3 and 4.
5. **Database down** at lookup (chain falls through to the server cache and remote sources) and at join (the join is unaffected, one warning per player per minute). Tests in Tasks 7 and 9.

### Task 7: Lookup chain

**Files:** `namebook-core/.../core/{chain/LookupChain,store/DatabaseSource}.java`; test `LookupChainTest`.

**Interfaces:**
- Consumes: `NameCache`, `PlayerStore`, `NameSource`, `PlayerNames`, `Resolution`, `SourceId`.
- Produces:
  - `final class DatabaseSource implements NameSource` wrapping `PlayerStore` on a given executor, plus `CompletableFuture<Map<UUID,String>> namesOf(Collection<UUID>)` and `CompletableFuture<Map<String,UUID>> uuidsOf(Collection<String>)`.
  - `final class LookupChain implements Namebook` — `LookupChain(NameCache cache, DatabaseSource database, List<NameSource> fallbacks /* in order: SERVER, PLAYERDB, MOJANG */, Executor executor, Logger log)`; plus `CompletableFuture<Resolution<String>> resolveName(UUID id)` and `CompletableFuture<Resolution<UUID>> resolveUuid(String name)` (used by the lookup command); `void recordLocally(UUID id, String name)` (cache only).
  - Behaviour: cache → database → fallbacks in order; first answer wins and is cached; all unknown → cache a miss; invalid names return unknown without touching any source; any source failure or exception is logged at FINE and treated as unknown; futures complete on `executor`.
  - Bulk: dedupe (names by `PlayerNames.key`), answer cache hits, one database call for the rest, then per-item fallbacks in parallel; result maps keep request order and the caller's spelling.
